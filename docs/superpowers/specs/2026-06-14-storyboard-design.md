# Storyboard Mode Design

## هدف

کالک نگار باید بتواند روی سناریوها یک حالت استوری برد داشته باشد که هم برای تدوین روایت استفاده شود و هم برای پخش روایت روی نقشه. این قابلیت باید با رویدادهای فعلی سناریو سازگار بماند، اما محدود به آن ها نباشد؛ یعنی کاربر بتواند از رویدادهای موجود صحنه بسازد یا صحنه های مستقل مثل مقدمه، تحلیل و جمع بندی اضافه کند.

## محدوده

این طراحی شامل مدل داده، رفتار تدوین، رفتار پخش، سازگاری با سناریوهای قدیمی، و تست های لازم است. پیاده سازی باید در `front_kalknegar` انجام شود و ذخیره سناریو همچنان از مسیرهای فعلی export/import و API محتوای سناریو عبور کند.

خارج از محدوده این مرحله:

- خروجی ویدیویی از استوری برد
- ضبط صوت یا narration صوتی
- ویرایشگر پیشرفته اسلاید
- تغییر مدل backend جدا از ذخیره JSON سناریو

## مدل داده

به مدل سناریو یک بخش اختیاری اضافه می شود:

```ts
storyboard?: {
  enabled: boolean;
  scenes: StoryboardScene[];
  settings: StoryboardSettings;
}
```

تنظیمات:

```ts
interface StoryboardSettings {
  defaultSceneDurationMs: number;
  autoDuration: boolean;
  showMode: "toast" | "cinematic";
}
```

صحنه:

```ts
interface StoryboardScene {
  id: string;
  title: string;
  body?: string;
  startTime?: number;
  durationMs?: number;
  order?: number;
  linkedEventId?: string;
  camera?: StoryboardCamera;
  pausePlayback?: boolean;
}
```

دوربین:

```ts
type StoryboardCamera =
  | { type: "none" }
  | { type: "eventWhere"; maxZoom?: number }
  | { type: "geometry"; geometry: unknown; maxZoom?: number }
  | { type: "units"; units: string[]; maxZoom?: number };
```

اگر `linkedEventId` وجود داشته باشد، صحنه می تواند عنوان، متن، زمان و موقعیت نقشه را از رویداد لینک شده بخواند. مقادیر خود صحنه اولویت دارند تا کاربر بتواند متن روایی متفاوتی برای همان رویداد بنویسد.

## رفتار تدوین

یک پنل یا تب جدید با عنوان استوری برد در ویرایشگر سناریو اضافه می شود.

قابلیت های پنل:

- نمایش لیست صحنه ها با ترتیب روایی
- ساخت صحنه از رویدادهای سناریو
- افزودن صحنه مستقل
- ویرایش عنوان، متن، زمان، مدت نمایش، ترتیب، لینک رویداد و رفتار دوربین
- تغییر ترتیب با drag/drop یا دکمه بالا/پایین
- نمایش وضعیت لینک به رویداد
- امکان قطع لینک و مستقل کردن صحنه
- هشدار برای صحنه هایی که به رویداد حذف شده لینک هستند

ترتیب پیش فرض صحنه ها با `order` تعیین می شود. اگر `order` تعریف نشده باشد، `startTime` معیار بعدی است. صحنه های بدون زمان بعد از صحنه های زمان دار قرار می گیرند مگر اینکه `order` داشته باشند.

## مدت نمایش

مدت نمایش هر صحنه به شکل ترکیبی محاسبه می شود:

1. اگر `durationMs` معتبر باشد، همان استفاده می شود.
2. اگر مقدار دستی وجود نداشته باشد و `autoDuration` فعال باشد، مدت بر اساس طول `title` و `body` محاسبه می شود.
3. اگر محاسبه خودکار ممکن نبود، `defaultSceneDurationMs` استفاده می شود.

فرمول پیشنهادی برای شروع:

- حداقل 4000 میلی ثانیه
- حداکثر 12000 میلی ثانیه
- پایه 3500 میلی ثانیه + حدود 45 میلی ثانیه برای هر کاراکتر متن

این فرمول باید در یک helper جدا تست پذیر باشد.

## رفتار پخش

دو حالت پخش داریم.

### پخش عادی

در پخش عادی سناریو، تغییر `currentTime` پایش می شود. وقتی زمان از `startTime` یک صحنه عبور کند، یک کارت کوتاه روی نقشه نمایش داده می شود. هر صحنه در یک اجرای پخش فقط یک بار نمایش داده می شود. اگر پخش از ابتدا یا زمان قبل از صحنه شروع شود، وضعیت نمایش صحنه ها reset می شود.

کارت عادی باید مستقل از notification عمومی باشد، چون متن استوری کنترل نمایش، ظاهر و طول متفاوتی نیاز دارد.

### Story Playback Mode

در حالت پخش استوری:

- UI ویرایش کم رنگ یا مخفی می شود.
- پخش بر اساس ترتیب صحنه ها جلو می رود، نه صرفا سرعت RAF فعلی.
- برای هر صحنه، زمان سناریو به `startTime` صحنه یا زمان رویداد لینک شده تنظیم می شود.
- کارت روایت در پایین یا کنار نقشه نمایش داده می شود.
- اگر دوربین تعریف شده باشد، نقشه به محل صحنه حرکت می کند.
- اگر `pausePlayback` فعال باشد، بعد از نمایش صحنه پخش متوقف می شود تا کاربر ادامه دهد.

اگر دوربین قابل اعمال نبود، متن همچنان نمایش داده می شود و پخش نباید fail کند.

## معماری پیشنهادی

یک composable جدا ساخته شود، مثلا:

```ts
useStoryboard(activeScenario)
```

مسئولیت ها:

- ساخت مقدار پیش فرض storyboard برای سناریوهای قدیمی
- ساخت scene از رویدادها
- resolve کردن scene لینک شده به رویداد
- مرتب سازی صحنه ها
- محاسبه مدت نمایش
- تشخیص sceneهای قابل نمایش هنگام عبور زمان
- reset وضعیت نمایش هنگام شروع دوباره پخش
- اجرای scene در Story Playback Mode

کامپوننت های پیشنهادی:

- `StoryboardPanel.vue`
- `StoryboardSceneForm.vue`
- `StoryboardSceneList.vue`
- `StoryboardOverlay.vue`
- `StoryboardPlaybackControls.vue`

کامپوننت overlay باید از state composable تغذیه شود و به notification عمومی وابسته نباشد.

## سازگاری

سناریوهای بدون `storyboard` باید بدون migration اجباری باز شوند. هنگام load، اگر بخش storyboard وجود نداشت، مقدار پیش فرض runtime ساخته می شود. هنگام ذخیره، اگر کاربر از قابلیت استفاده کرده باشد، storyboard در payload سناریو ذخیره می شود.

اگر scene به رویدادی لینک باشد که حذف شده است:

- scene حذف نمی شود.
- در پنل تدوین هشدار نمایش داده می شود.
- در پخش، از داده های خود scene استفاده می شود.
- اگر داده کافی نبود، scene skip می شود و خطا به صورت غیرمسدودکننده ثبت می شود.

## خطاها

- duration نامعتبر: استفاده از duration هوشمند یا پیش فرض
- camera نامعتبر: نمایش متن بدون حرکت دوربین
- رویداد لینک شده حذف شده: هشدار تدوین و fallback به داده scene
- متن خالی: نمایش فقط عنوان؛ اگر عنوان هم خالی بود، scene در پخش skip شود
- زمان نامعتبر: صحنه فقط در Story Playback با ترتیب روایی قابل نمایش باشد، نه در پخش عادی زمان محور

## تست

تست های unit:

- مرتب سازی صحنه ها بر اساس `order` و سپس `startTime`
- محاسبه duration هوشمند با حداقل و حداکثر
- ساخت scene از `ScenarioEvent`
- resolve کردن scene لینک شده و override شدن فیلدهای صحنه
- تشخیص عبور زمان و نمایش یک باره scene
- reset شدن نمایش sceneها هنگام برگشت زمان یا شروع مجدد پخش
- سازگاری سناریوی قدیمی بدون `storyboard`
- fallback برای linked event حذف شده

تست های UI محدود:

- نمایش پنل استوری برد با سناریوی بدون storyboard
- افزودن صحنه مستقل
- ساخت صحنه از رویدادها
- نمایش overlay هنگام فعال شدن scene

## ریسک ها

- ترکیب پخش زمان محور فعلی با پخش استوری می تواند باعث نمایش تکراری شود. باید state نمایش صحنه ها در composable مرکزی نگه داشته شود.
- تغییر مدل سناریو باید با import/export قدیمی سازگار بماند. فیلد `storyboard` باید اختیاری باشد.
- اگر overlay به notification عمومی وصل شود، کنترل رفتار روایت سخت می شود. overlay مستقل ریسک را کاهش می دهد.

## معیار پذیرش

- کاربر بتواند از رویدادهای موجود صحنه بسازد.
- کاربر بتواند صحنه مستقل اضافه کند.
- کاربر بتواند ترتیب روایی را مستقل از زمان override کند.
- duration هر صحنه یا دستی باشد یا هوشمند محاسبه شود.
- در پخش عادی، عبور از زمان صحنه کارت کوتاه نشان دهد.
- در Story Playback Mode، صحنه ها به ترتیب روایی پخش شوند و نقشه در صورت امکان به محل صحنه حرکت کند.
- سناریوهای قدیمی بدون تغییر باز و ذخیره شوند.
