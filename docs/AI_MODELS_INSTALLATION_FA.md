# راهنمای نصب و اتصال مدل‌های هوش مصنوعی سامانه ساجد

این راهنما برای نصب محلی مدل‌های مورد استفاده در بخش «کالک‌یار» تهیه شده است.
مدل‌ها روی رایانه یا سرور کارفرما اجرا می‌شوند و سامانه از طریق یک رابط محلی با آن‌ها
ارتباط برقرار می‌کند. برای بهره‌برداری عادی، ارسال سند به سرویس بیرونی الزامی نیست.

## ۱. کاربرد مدل‌ها در سامانه

سامانه از دو قابلیت جداگانه استفاده می‌کند:

| قابلیت | مدل پیش‌فرض | کاربرد |
|---|---|---|
| تحلیل متن | `qwen/qwen3.5-9b` | استخراج پیشنهادهای سناریو، اشخاص، یگان‌ها، تجهیزات، مکان‌ها و رویدادها از متن و استانداردسازی اکسل |
| خواندن تصویر و سند | `paddlepaddle/paddleocr-vl-1.5-gguf/paddleocr-vl-1.5.gguf` | خواندن صفحات اسکن‌شده، تصاویر و پرونده‌های بدون متن قابل‌استخراج |

### فایل‌های لازم برای انتقال به سرور

برای دو مدل بالا، چهار فایل زیر باید منتقل شوند:

```text
Qwen3.5-9B-Q4_K_M.gguf
mmproj-Qwen3.5-9B-BF16.gguf
PaddleOCR-VL-1.5.gguf
mmproj-PaddleOCR-VL-1.5-BF16.gguf
```

فایل‌های `mmproj` مدل مستقل نیستند؛ بخش تصویرنگار مدل متناظر هستند. فایل دیگری با نام
زیر نیز در مبدا وجود دارد، اما اثر انگشت آن با تصویرنگار مدل بازشناسی یکسان است و یک
رونوشت تکراری محسوب می‌شود:

```text
PaddleOCR-VL-1.5-mmproj.gguf
```

بنابراین مسئول سرور باید دو مدل و چهار فایل ضروری را منتقل کند، نه پنج فایل را.

برای اسناد چندستونه، جدول‌های پیچیده و نقشه‌ها، استفاده از سرویس کامل
`PaddleOCR-VL` نیز توصیه می‌شود. این سرویس صفحه‌آرایی و ترتیب خواندن را بهتر از مسیر
ساده مدل بینایی تشخیص می‌دهد.

## ۲. پیش‌نیازهای پیشنهادی

- ویندوز ده یا یازده ۶۴بیتی، یا یک سرور لینوکسی مناسب؛
- دست‌کم ۳۲ گیگابایت حافظه اصلی برای اجرای روان‌تر؛
- کارت گرافیک سازگار با انویدیا و دست‌کم ۱۲ گیگابایت حافظه تصویری؛
- برای اجرای هم‌زمان دو مدل، ۱۶ گیگابایت حافظه تصویری یا بیشتر پیشنهاد می‌شود؛
- حدود ۳۰ تا ۶۰ گیگابایت فضای آزاد برای مدل‌ها، تصویرهای داکر و پرونده‌های موقت؛
- نصب بودن `Docker Desktop` برای اجرای سامانه و سرویس کامل بازشناسی سند؛
- دسترسی اینترنت فقط برای نصب اولیه و دریافت مدل‌ها و تصویرهای داکر.

مقادیر بالا پیشنهاد عملی هستند و مقدار دقیق مصرف حافظه به نوع فشرده‌سازی مدل، طول
بافت و تعداد درخواست‌های هم‌زمان بستگی دارد. پیش از خرید یا تخصیص سخت‌افزار، اجرای یک
سند واقعی روی همان دستگاه آزمایش شود.

## ۳. روش ساده نصب با نرم‌افزار مدیریت مدل

### ۳.۱. نصب نرم‌افزار

آخرین نسخه `LM Studio` را از نشانی رسمی زیر دریافت و نصب کنید:

https://lmstudio.ai/download

پس از نصب، در بخش دریافت مدل‌ها که با عنوان `Discover` نمایش داده می‌شود، دو مدل
زیر را جست‌وجو و دریافت کنید:

```text
qwen/qwen3.5-9b
paddlepaddle/paddleocr-vl-1.5-gguf
```

برای مدل‌های دارای چند نسخه فشرده، نسخه‌ای را انتخاب کنید که با حافظه کارت گرافیک
دستگاه سازگار باشد. در دستگاه‌های دارای حافظه محدود، نسخه‌های چهار بیتی معمولاً انتخاب
عملی‌تری هستند.

### ۳.۲. بارگذاری مدل‌ها

پس از پایان دریافت، مدل تحلیل متن و مدل بینایی را بارگذاری کنید. مدل بینایی باید همراه
بخش پردازش تصویر خود بارگذاری شود. اگر حافظه دستگاه برای نگه‌داشتن هم‌زمان هر دو مدل
کافی نیست، می‌توان برای هر مدل یک سرویس جداگانه روی درگاه متفاوت اجرا کرد و نشانی هر
سرویس را جداگانه در تنظیمات سامانه قرار داد.

شناسه نمایشی مدل بارگذاری‌شده باید با مقدار ثبت‌شده در فایل محیطی سامانه برابر باشد.
اگر نرم‌افزار شناسه دیگری نمایش داد، همان شناسه نمایش‌داده‌شده را در متغیر مربوط به مدل
وارد کنید.

### ۳.۳. فعال‌کردن رابط محلی

در بخش توسعه‌دهنده نرم‌افزار، سرویس محلی را روی درگاه `1234` راه‌اندازی کنید. دسترسی
از شبکه محلی میزبان را فعال کنید تا ظرف داکر سامانه بتواند به آن متصل شود. این درگاه
نباید بدون دیواره آتش یا کنترل دسترسی در اینترنت عمومی منتشر شود.

در صورت نصب بودن ابزار خط فرمان، فرمان معادل برای شروع سرویس چنین است:

```powershell
lms server start --port 1234 --bind 0.0.0.0
```

برای بررسی دسترسی و مشاهده شناسه دقیق مدل‌های بارگذاری‌شده، فرمان زیر را اجرا کنید:

```powershell
Invoke-RestMethod http://127.0.0.1:1234/v1/models
```

پاسخ باید شامل هر دو شناسه مدل باشد. خالی بودن فهرست به این معناست که سرویس اجرا شده،
اما هنوز مدلی در حافظه بارگذاری نشده است.

## ۴. تنظیم اتصال در سامانه ساجد

در پوشه اصلی پروژه، اگر فایل محیطی وجود ندارد، آن را از نمونه موجود بسازید:

```powershell
Copy-Item .env.example .env
```

مقادیر زیر را در پرونده `.env` بررسی یا تنظیم کنید:

```text
INTERNAL_LLM_BASE_URL=http://host.docker.internal:1234
INTERNAL_LLM_API_KEY=
INTERNAL_LLM_MODEL=qwen/qwen3.5-9b

DOCUMENT_LLM_BASE_URL=http://host.docker.internal:1234
DOCUMENT_LLM_MODEL=qwen/qwen3.5-9b
DOCUMENT_OCR_BASE_URL=http://host.docker.internal:1234
DOCUMENT_OCR_MODEL=paddlepaddle/paddleocr-vl-1.5-gguf/paddleocr-vl-1.5.gguf
DOCUMENT_OCR_PIPELINE_URL=
```

نشانی `host.docker.internal` مخصوص حالتی است که مدل روی رایانه میزبان و سامانه داخل
داکر اجرا می‌شود. اگر مدل روی سرور دیگری قرار دارد، این نشانی باید با نشانی همان سرور
جایگزین شود.

اگر برای رابط مدل کلید دسترسی تعریف شده است، مقدار آن فقط در پرونده محلی `.env` ثبت
شود:

```text
INTERNAL_LLM_API_KEY=YOUR_LOCAL_API_TOKEN
```

پرونده `.env` حاوی گذرواژه‌ها و کلیدها است و نباید در گیت، پیام‌رسان یا مستندات تحویل
قرار گیرد.

پس از ذخیره تنظیمات، رابط برنامه را بازسازی و اجرا کنید:

```powershell
docker compose up -d --build api
```

برای مشاهده وضعیت رابط برنامه، فرمان زیر قابل استفاده است:

```powershell
docker compose ps api
docker compose logs --tail 100 api
```

## ۵. نصب اختیاری سرویس کامل بازشناسی سند

این بخش برای پردازش دقیق‌تر صفحه‌آرایی، جدول‌ها و اسناد تصویری است. ابتدا مخزن رسمی
را در پوشه‌ای جدا از پروژه ساجد دریافت کنید:

```powershell
git clone https://github.com/PaddlePaddle/PaddleOCR.git
Set-Location PaddleOCR
```

پوشه شتاب‌دهنده باید با سخت‌افزار سرور انتخاب شود. برای کارت‌های خانواده بلک‌ول با
قابلیت محاسباتی `sm120`، مسیر زیر در مخزن رسمی وجود دارد:

```powershell
Set-Location deploy/paddleocr_vl_docker/accelerators/nvidia-gpu-sm120
```

این مسیر نباید بدون بررسی برای همه کارت‌های گرافیک استفاده شود. برای سخت‌افزارهای
دیگر، پوشه و راهنمای متناظر در مخزن رسمی `PaddleOCR` انتخاب شود.

در نسخه فعلی مخزن رسمی، پرونده محیطی این مسیر باید شامل مقادیر زیر باشد:

```text
API_IMAGE_TAG_SUFFIX=latest-nvidia-gpu-sm120-offline
VLM_BACKEND=vllm
VLM_IMAGE_TAG_SUFFIX=latest-nvidia-gpu-sm120-offline
```

سرویس را اجرا کنید:

```powershell
docker compose up -d
```

راه‌اندازی نخست ممکن است به دلیل دریافت تصویرهای بزرگ و آماده‌شدن مدل چند دقیقه زمان
ببرد. سلامت سرویس را با فرمان زیر بررسی کنید:

```powershell
Invoke-RestMethod http://127.0.0.1:8080/health
```

سپس مقدار زیر را در پرونده `.env` سامانه ساجد قرار دهید:

```text
DOCUMENT_OCR_PIPELINE_URL=http://host.docker.internal:8080
```

پس از تغییر تنظیم، رابط برنامه را بازسازی کنید:

```powershell
docker compose up -d --build api
```

اگر درگاه `8080` روی سرور قبلاً استفاده شده است، نگاشت درگاه سرویس بازشناسی را تغییر
دهید و همان درگاه جدید را در `DOCUMENT_OCR_PIPELINE_URL` ثبت کنید. در خود پروژه ساجد،
سرویس اختیاری نقشه سازمانی نیز در نمایه `sdi` از همین درگاه استفاده می‌کند؛ بنابراین
هنگام فعال‌بودن آن نمایه باید برای یکی از این دو سرویس درگاه دیگری تعیین شود.

## ۶. آزمون پذیرش

پس از ورود به سامانه، به بخش «مدیریت داده‌ها» و سپس «کالک‌یار» بروید. پیش از انتخاب
سند، وضعیت مدل تحلیل متن و مدل خواندن تصویر باید «آماده» نمایش داده شود.

برای آزمون نهایی، یک پرونده کوچک شامل متن فارسی، عدد، جدول و تصویر انتخاب کنید. نتیجه
باید ابتدا به‌صورت پیشنهاد قابل‌بازبینی نمایش داده شود. سامانه در این مرحله نباید
داده‌ای را خودکار در سناریو یا فهرست منابع ثبت کند.

پذیرش نصب زمانی انجام می‌شود که موارد زیر تأیید شده باشند:

- هر دو مدل در فهرست سرویس محلی دیده می‌شوند؛
- وضعیت مدل‌ها در کالک‌یار آماده است؛
- یک صفحه متنی و یک صفحه تصویری بدون خطای ارتباط پردازش می‌شوند؛
- شماره صفحه و شاهد متنی در نتیجه وجود دارد؛
- بستن یا تازه‌سازی مرورگر، کار سروری در حال پردازش را از بین نمی‌برد؛
- هیچ پیشنهاد تأییدنشده‌ای مستقیماً وارد داده‌های اصلی نمی‌شود.

## ۷. خطاهای متداول

| نشانه | علت محتمل | اقدام پیشنهادی |
|---|---|---|
| فهرست مدل‌ها خالی است | مدل دریافت شده ولی بارگذاری نشده است | مدل را در نرم‌افزار مدیریت مدل بارگذاری کنید |
| مدل در نرم‌افزار دیده می‌شود ولی در کالک‌یار آماده نیست | شناسه مدل یا نشانی سرویس با `.env` برابر نیست | خروجی `/v1/models` را با متغیرهای مدل مقایسه کنید |
| خطای اتصال از داخل داکر | سرویس فقط روی نشانی محلی محدود شده یا دیواره آتش مانع است | دسترسی شبکه محلی سرویس را فعال و درگاه را فقط برای شبکه مورد نیاز مجاز کنید |
| خطای کمبود حافظه | دو مدل هم‌زمان یا با بافت بزرگ بارگذاری شده‌اند | نسخه فشرده‌تر، بافت کوتاه‌تر یا سرویس‌های جداگانه استفاده شود |
| متن ساده خوانده می‌شود ولی جدول به‌هم می‌ریزد | فقط مسیر ساده مدل بینایی فعال است | سرویس کامل `PaddleOCR-VL` را نصب و نشانی زنجیره بازشناسی را تنظیم کنید |
| سرویس بازشناسی دیر آماده می‌شود | تصویرها در حال دریافت یا مدل در حال بارگذاری است | وضعیت ظرف‌ها و گزارش آن‌ها را بررسی و تا پایان دوره آغاز سرویس صبر کنید |

## ۸. نکات امنیتی و نگهداری

- رابط مدل فقط در شبکه داخلی در دسترس باشد و مستقیماً در اینترنت عمومی منتشر نشود؛
- کلید دسترسی، گذرواژه و پرونده `.env` در مخزن گیت قرار نگیرد؛
- نسخه مدل، نوع فشرده‌سازی و تاریخ نصب در صورت‌جلسه استقرار ثبت شود؛
- پیش از به‌روزرسانی مدل، یک مجموعه ثابت از اسناد نمونه نگهداری و نتیجه نسخه جدید با
  نسخه قبلی مقایسه شود؛
- خروجی مدل پیشنهاد اولیه است و تأیید انسانی پیش از ورود اطلاعات به سامانه الزامی است؛
- برای پوشه پرونده‌های پردازش سند، سیاست نگهداری، حذف دوره‌ای و پشتیبان‌گیری تعیین شود.
